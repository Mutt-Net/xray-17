# Release 2026.6.2 — DX10/DX11 Correctness

**Tag:** `2026.6.2`
**Branch:** `cmake`
**Base:** S.T.A.L.K.E.R. Anomaly 1.5.3 (X-Ray Monolith Edition, community fork)
**Build verified:** RelWithDebInfo — MSVC (VS Build Tools 18) + Ninja, 2942/2942 steps, all four DX targets linked clean (2026-06-01).

---

## Summary

This release consolidates two correctness sprints into the `cmake` branch. It is a
**stability and rendering-correctness release** — there are no new gameplay features.
The work targets long-standing defects in the DX10/DX11 render paths, several of which
were crashes or silent rendering failures inherited from an incomplete DX9→DX10 port.

Every change is documented at commit granularity in
[`docs/muttcode-changes.md`](../muttcode-changes.md) with symptom, root cause, exact
before/after code, and commit reference, so each fix can be reviewed or cherry-picked
independently.

---

## Why this release matters

The DX10 (R3) and DX11 (R4) renderers in this engine lineage were ported from the
original DX9 (R2) path. That port was never fully completed: large blocks of code were
left commented out as `/* DX10 cut */`, several functions were stubbed with
`VERIFY(!"Not implemented.")` crash guards, and a long tail of `// TODO: DX10:` markers
recorded work that was started but not finished.

This release closes the highest-impact gaps in that backlog:

- **Two crash sites** that could fire in normal play (`set_AlphaRef`, R4 async screenshot)
- **One entirely unimplemented feature** restored (cube render targets / `CRTC`)
- **One broken display mode** fixed (HDR10 on the DX10 renderer)
- **One per-frame D3D debug-layer error** eliminated (MSAA volumetric accumulator)
- A **resource leak** and several smaller correctness issues

## Changes

### Crashes fixed

| Area | Symptom | Fix |
|------|---------|-----|
| `CBackend::set_AlphaRef` | Hard assert (`VERIFY(!"Not implemented.")`) if any UI path set an alpha reference on DX10/11 | Converted to a documented no-op — DX10+ has no hardware alpha-ref register; alpha test is shader-side via `clip()`. Commit `e65c07ee` |
| R4 async screenshot | `__uuidof(ID3D10Texture2D)` on a DX11 swapchain returns `E_NOINTERFACE`, guaranteeing a null-dereference crash on screenshot | Corrected to `__uuidof(ID3DTexture2D)` (resolves to `ID3D11Texture2D` under DX11) + added `hr` check. Commit `f67ebd2c` |

### Rendering correctness

| Area | Symptom | Fix |
|------|---------|-----|
| Cube render targets (`CRTC`) | Class and resource-manager hooks were entirely commented out (`/* DX10 cut */`) — any cube-RT effect produced null surfaces | Full DX10/11 port: `ID3DTexture2D` array (`ArraySize=6`, `MISC_TEXTURECUBE`) with per-face `ID3DRenderTargetView`. Also fixed an inverted `valid()` predicate. Commits `02d1738e`, `a5ee052c`, `5b51435a` |
| HDR10 on DX10 | `ps_r4_hdr10_on` had no effect on the DX10 renderer — backbuffer was always 8-bit SDR | DX10 backbuffer format now follows the cvar (`R10G10B10A2_UNORM` for HDR10) and the `IDXGISwapChain3` colour space is configured, matching the DX11 path. Commits `d6b5eb8b`, `791eb3ee`, `a0ef3fad` |
| RT format support | `CRT::create` called `CreateTexture2D` with no device-capability check — unsupported formats hard-failed | Added `CheckFormatSupport` validation with new `D3D_FORMAT_SUPPORT_*` aliases. Commits `3ee2a20f`, `2ecde80a` |
| MSAA volumetric accumulator | RT/depth sample-count mismatch produced a D3D debug-layer error every frame with MSAA enabled | Pass `NULL` depth — additive accumulation needs no depth-stencil view. Commit `4b2f6cb8` |
| Sun shafts | Shaft pass ran even with a fully black sun | Gated on `sun_color.square_magnitude()`. Commit `0669138b` |
| A2R10G10B10 mapping | Undocumented `// gross hack` format mapping; `A2B10G10R10` entry missing | Documented channel-order divergence; restored `A2B10G10R10`. Commit `74f6a88c` |

### Resource management

| Area | Symptom | Fix |
|------|---------|-----|
| Async screenshot (R3 + R4) | `GetBuffer` COM reference never released — one texture leaked per screenshot | Added `pBuffer->Release()` after `CopyResource`. Commit `f67ebd2c` |

### Hygiene

| Area | Change |
|------|--------|
| Windowed refresh rate | `{60,1}` → DXGI-neutral `{0,0}`; removes validation warnings on non-60 Hz displays. Commit `b31cfba0` |
| Investigation TODOs | ~12 stale `// TODO: DX10:` markers across 9 files converted to explanatory knowledge comments — no behaviour change. Commit `4b2f6cb8` |
| Render triage | [`docs/render-todo-triage.md`](../render-todo-triage.md) Groups A–I updated to reflect resolution status |
| Build | Disabled IPO / stripped LTCG for RelWithDebInfo (link stability); `static` on explicit template specialisations. Commits `ed736fdc`, `77a476bc` |

## Installation

1. Back up your existing `bin/` executables in the S.T.A.L.K.E.R. Anomaly install.
2. Copy `AnomalyDX8.exe`, `AnomalyDX9.exe`, `AnomalyDX10.exe`, `AnomalyDX11.exe` from the
   release `bin/` folder into your Anomaly `bin/` directory.
3. Copy the gamedata `.db0` from the release `db/mods/` folder into your Anomaly
   `db/mods/` directory.
4. Launch via your normal launcher; pick the DX level matching the executable.

The attached archive includes **both** the regular and AVX executables for all four
DX levels, plus packed gamedata. Use the `*AVX.exe` build if your CPU supports AVX
(any gaming CPU since ~2013); otherwise use the regular build.

**HDR10:** set `ps_r4_hdr10_on 1` in console or user.ltx. As of this release, HDR10 now
functions on **both** the DX10 and DX11 renderers (previously DX11-only).

## Known issues / not addressed

These are tracked for future work — see
[`docs/future-development.md`](../future-development.md):

- **Cube RT port is half-complete.** The DX10/11 side is done; the shared `xrRender`
  resource manager (DX9 path and the reset-time dump) still carries `/* DX10 cut */`
  blocks for `_CreateRTC`/`_DeleteRTC`.
- **`CBackend::set_xform`** retains a commented-out `VERIFY` and is effectively a stub on
  DX10/11.
- **`nullrt` R5G6B5→R8G8B8A8** mapping remains a documented workaround.
- Group H of the render triage still lists open device-layer items (shader resource
  HACK, scripting paths, DX9 state-cache leftovers, triangle-fan topology).
- No automated render-regression tests exist; verification is visual against a DX9
  reference.
